# Локальное обучение голосовых моделей

## Персональный классификатор команд

Рецепт использует исходный классификатор из `.runtime/local-voice/baseline/command-model`, синтетические обучающие примеры первого прогона и полные WAV из `.runtime/local-voice/drive`. Файл `.runtime/personal-command-v2/labels.json` хранит по одной строке на запись — имя исходного WAV, SHA-256, час записи, класс команды, источник метки и выборку `development` или `holdout`. Разметка `null` исключает неоднозначные записи. Класс `unknown` означает, что в записи отсутствует одна из десяти поддерживаемых акустических команд.

```powershell
$env:PYTHONPATH=(Resolve-Path '.runtime/wake-validation').Path
$env:OPENBLAS_NUM_THREADS='1'
$env:PYTHONUTF8='1'
.runtime/voice/Scripts/python.exe word_training/personal_commands.py --minutes 40
.runtime/voice/Scripts/python.exe word_training/compare_personal_commands.py --criterion direct-controls --install-if-better
```

Программа обучает добавочную голову на GPU и по очереди оставляет один час записей для проверки внутри обучающей части. В финальном сравнении обе версии получают через `command_detect` каждый отложенный WAV целиком, один раз, при одинаковом рабочем пороге. Отчёт `.runtime/personal-command-v2/comparison.json` содержит эталонный класс, ответы и уверенность обеих моделей для каждой записи. Без ключа `--install-if-better` команда только сравнивает версии.

Критерий по умолчанию `class-and-action` учитывает отдельно верно распознанные пользовательские команды и верные управляющие действия выше порога. Хотя бы один из двух показателей должен вырасти при сохранении второго, общей точности и числа ошибочных действий на уровне исходной модели или лучше. После замены программа повторяет тест через стандартный путь загрузки бота.

Для этого бота владелец выбрал приоритет прямых действий. Его можно воспроизвести флагами `--criterion direct-controls --install-if-better`. Такой режим требует больше верных действий при том же пороге, без роста числа ошибочных действий или снижения общей точности на всех отложенных примерах. В отчёте сохраняются результаты обоих критериев.

В прогоне 27 ноября для обучения использованы 36 записей Discord из пяти часовых групп. Они дали 2 340 окон с аугментациями. Для сохранения остальных классов добавлены 13 200 синтетических обучающих окон. Из других двух часов отложены 12 исходных WAV, семь из них впервые участвовали в оценке классификатора. Для фраз «выйди / выйдем» и «бесконечный режим» владелец подтвердил требуемые действия.

| На личных записях при пороге 0,85 | Исходный v3 | Персональный v2 |
|---|---:|---:|
| Верный класс на всех 12 примерах | 11 | 11 |
| Верный класс на 11 настоящих командах | 11 | 10 |
| Верные прямые действия из 7 команд управления | 3 | 6 |
| Ошибочные прямые действия | 0 | 0 |

Персональный классификатор установлен в `models/command-model`. Он принял три дополнительные команды отключения. На одной записи «следующий» он выбрал `unknown`. Обе версии передали её на распознавание речи. На отдельном синтетическом тесте из 2 296 окон число верных классов выросло с 1 968 до 2 023, ошибочных прямых действий стало 71 вместо 107. На тех же 84 окнах для каждого класса верных распознаваний повтора стало 48 вместо 57, очистки очереди — 63 вместо 77.

## Адаптация двух моделей бота на записях Discord

Локальный рецепт дообучает выходные слои детектора «бот» и классификатора 11 действий на CUDA. Для каждого двухсекундного окна исходная INT8-модель вычисляет признаки на CPU в том же режиме, что и бот. Градиенты на GPU обучают добавочную нелинейную голову. При экспорте она входит в тот же ONNX-граф. Пороги и сопоставление классов действиям берутся из исходных конфигураций.

Из корня проекта в подготовленном Windows-окружении:

```powershell
$env:PYTHONPATH=(Resolve-Path '.runtime/wake-validation').Path
$env:OPENBLAS_NUM_THREADS='1'
$env:PYTHONUTF8='1'
.runtime/voice/Scripts/python.exe word_training/synthesize_local.py
.runtime/voice/Scripts/python.exe word_training/local_corpus.py
.runtime/voice/Scripts/python.exe word_training/train_local_audio.py --minutes 18
```

Для повторного обучения на готовом корпусе достаточно последней команды с теми же переменными окружения. Если рабочие модели уже заменены, укажите каталог исходной пары через `--base .runtime/local-voice/baseline`. Обучение использует PyTorch с CUDA, NumPy, ONNX и ONNX Runtime. Для синтеза дополнительно нужны окружение прежнего TTS-рецепта и Silero `tts/v5_5_ru.pt` в каталоге `--tts-work`. Аргумент `local_corpus.py --legacy` принимает прежний манифест wakeword с исходными WAV или индексированными массивами PCM.

* `.runtime/local-voice/drive/` — оригинальные WAV из Google Диска. Для новой партии можно запустить `transcribe_archive.py КАТАЛОГ_WAV ЛОКАЛЬНАЯ_МОДЕЛЬ_WHISPER РЕЗУЛЬТАТ.json` с двумя локальными моделями faster-whisper. Расшифровки привязаны к началу и длине окна.
* `real-labels.json` — отобранные окна архива. Каждая строка массива содержит `file` относительно рабочего каталога, `start` в отсчётах 16 кГц, `source` (исходная запись), `group` (сеанс), `origin: "drive"`, `split`, `wake` (0, 1 или null), `command` (класс из command_config.json или null) и происхождение метки. Неоднозначную метку можно пропустить отдельно для каждой задачи. Новые сеансы распределяются целиком до построения аугментаций.
* `audio.npy` — готовые окна PCM16 размером 32 000 отсчётов. Номер окна, выборка, происхождение, метки и номер варианта доступны в `windows.jsonl`. Нулевой вариант сохраняет исходную громкость. Остальные меняют темп, положение фразы, уровень сигнала, шум и отражения. Тестовые записи Discord оцениваются однократно без аугментации. Новые голоса Silero разделены между выборками. Старый wakeword-корпус служит отдельной регрессионной проверкой с прежним разбиением.
* `candidates/wake-model/` и `candidates/command-model/` — совместимые с ботом каталоги для `WAKE_MODEL_PATH` и `COMMAND_MODEL_PATH`. Обучающий скрипт оставляет выбор рабочей версии за владельцем. В `report.json` записаны время, GPU, контрольные суммы и сравнение с исходными моделями по источнику. Для wakeword считаются пропуски и ложные срабатывания на окно. Для команд отдельно считаются ошибочные действия, прошедшие рабочий порог. Эпоха выбирается на validation, затем один раз оценивается test. Бюджет времени охватывает извлечение признаков и обучение двух голов. Скачивание, расшифровка и синтез выполняются до него.

### Первый прогон от 27 ноября 2026

На RTX 3070 полный проход после сборки датасета занял 102 секунды, включая 78 секунд вычисления признаков обоих энкодеров. Корпус содержит 16 940 обучающих, 1 287 валидационных и 3 256 тестовых окон. Для задачи команд метки есть у 13 368, 724 и 2 301 окна соответственно. Расширенные варианты одной исходной записи зависимы. В тесте нового синтеза 164 исходные записи одного отложенного голоса и 2 296 окон с вариантами звучания.

Из 59 записей Discord удалось присвоить метки 25 записям по двум локальным расшифровкам. Спорные произнесения «бот/вот» исключены. Для группировки использовался час записи по имени файла. Личности говорящих и реальные границы разговоров неизвестны. Из шести архивных тестовых записей все шесть имеют отрицательную метку wakeword, у пяти также есть метка команды. Данных для оценки полноты обнаружения «бот» на живом голосе в этом тесте нет.

| Проверка через голосовой процесс бота | Исходная модель | После обучения |
|---|---:|---:|
| Обнаружено «бот» из 774 положительных окон | 660 (85,3%) | 719 (92,9%) |
| Ложные срабатывания на 2 482 отрицательных окнах | 0 | 2 (0,08%) |
| Верный класс команды из 2 301 окна | 1 973 (85,7%) | 2 137 (92,9%) |
| Ошибочные команды управления выше рабочего порога | 107 | 49 |
| Верный класс на пяти записях Discord | 5 | 4 |

В `models/wake-model` установлен новый детектор. Классификатор команд сохранён в `.runtime/local-voice/candidates/command-model` для отдельного испытания. На одном архивном примере он вернул `unknown` вместо `stop`. У исходной модели уверенность в `stop` также оказалась ниже рабочего порога 0,85. В обоих случаях голосовой процесс передаёт команду на распознавание речи. Исходная пара доступна в `.runtime/local-voice/baseline`.

## Обучение одного слова с нуля

Модель обнаруживает целое слово **«бот» в любой фразе**. «Бот, включи музыку» —
положительный пример; «робот», «боту», «кот», «борт», речь без слова и шум — отрицательные.
Модель выдаёт вероятность/факт обнаружения, не текст, команды или намерения.

Обучение использует локальную CUDA GPU, Silero v4/v5.5, четыре русских Piper-голоса
и MMS. Пунктуация/просодия варьируются у обоих классов. Добавляются независимые
pitch, темп, шум, реверберация, громкость и реальные негативные Speech Commands.
Голоса train/validation/calibration/test разделены; слово при аугментации не обрезается.
В рецепте v2 половина положительных примеров содержит только слово, половина —
слово в короткой фразе. Всего 29 850 окон, из них 19 416 используются для обучения.

Whisper Tiny encoder дообучает все четыре слоя и бинарную голову. AMP, EMA,
баланс классов/движков и поиск сложных примеров используют только train.
Validation выбирает checkpoint/FP32 или INT8; calibration фиксирует порог.
Test не используется для подбора порога. Цель — максимальный recall при FPR
не выше 0,5% отрицательных окон; качество на реальных пользователях определяется
отдельной проверкой. 90% не считаются достигнутыми до получения результатов.

Из корня проекта, в уже подготовленном Python-окружении:

```powershell
$env:PYTHONIOENCODING='utf-8'
.runtime/voice/Scripts/python.exe word_training/train.py --word бот --run bot-v2
```

Продолжить прерванный запуск с тем же рецептом: добавить `--resume`.
Для другого слова/рецепта задайте новое имя `--run`; исходники и метки проверяют
границы слова. Русские похожие отрицательные слова находятся в `data.py`.

После завершения запуска можно сравнить шаг обучения на тех же данных:

```powershell
.runtime/voice/Scripts/python.exe word_training/compare.py --run bot-v2 --comparison learning-rate
```

Сравнение сохраняет первоначальный результат и выбирает одну модель на validation.
Результаты выполненного локального обучения приведены в [RESULTS.md](RESULTS.md).

Следующее улучшение на тех же русских проверочных записях:

```powershell
.runtime/voice/Scripts/python.exe word_training/expand_voices.py --source bot-v2 --run bot-data-v3
.runtime/voice/Scripts/python.exe word_training/improve.py --source bot-data-v3 --run bot-binary-v3
```

В `bot-data-v3` добавлены восемь британских голосов Kokoro, 8000 примеров
«bot» с близким произношением и 8000 похожих отрицательных слов. Это добавочные
акустические варианты целевого слова; русский тест и его метки не меняются.
Данные содержат 45 850 окон, train — 35 416. Упакованные аудио и признаки
читаются по индексам, без создания дополнительных десятков тысяч файлов.
`improve.py` начинает с лучших весов v2, добавляет частотную аугментацию и
сохраняет исходный результат. Прерванное обучение восстанавливается с `--resume`.

Отдельные экспериментальные способы, не заменяющие выбранную модель автоматически:

```powershell
.runtime/voice/Scripts/python.exe word_training/teacher_phonetic.py --source bot-data-v3 --run bot-phonetic-tiny-v3
.runtime/voice/Scripts/python.exe word_training/train_phonetic.py --source bot-data-v3 --run bot-phonetic-tiny-v3 --backbone tiny
.runtime/voice/Scripts/python.exe word_training/acoustic_teacher.py --source bot-data-v3 --run bot-large-acoustic-v3
```

Русская модель `jonatasgrosman/wav2vec2-large-xlsr-53-russian`, revision
`ab9492f472b7de03e79117b4187ed7bf385af3e1`, хранится локально в
`.runtime/wake-phonetic-teacher`. Фонетический студент обучается на разметке
звуков «б», «о», «т», границы и других звуков. Конечный автомат CTC внутри
ONNX отвергает последовательности, принадлежащие более длинному слову.
Акустический teacher использует замороженный энкодер и обучаемую бинарную голову;
его текстовый словарь и текстовые ответы не используются. Его кэш мягких
ответов содержит только train. Для дистилляции в компактный бинарный студент:

```powershell
.runtime/voice/Scripts/python.exe word_training/improve.py --run bot-distilled-v3 --teacher bot-large-acoustic-v3
```

Это имеет смысл только после проверки качества teacher на validation.
Команды обучения на одной GPU выполняйте последовательно. `choose.py` сравнивает
завершённые v2/v3 модели и комбинации на validation, фиксирует модель, затем
калибрует порог и открывает test. Добавочный бинарный студент передаётся через
`--extra bot-distilled-v3`. Итоговый ZIP содержит только runtime.

Дополнительные три украинских голоса Piper используются как фонетические
прокси кириллического «бот», с явной меткой языка `uk` и балансировкой вместе
с русским целевым словом. Неподдерживаемые буквенные тексты исключаются: TTS
не должен превратить отрицательное «боты» в положительное «бот», отбросив букву.

```powershell
.runtime/voice/Scripts/python.exe word_training/expand_slavic.py
.runtime/voice/Scripts/python.exe word_training/improve.py --source bot-data-v4 --run bot-binary-v4 --initial bot-binary-v3/checkpoints/best.pt
```

Небольшая дополнительная временная свёртка перед объединением признаков слова:

```powershell
.runtime/voice/Scripts/python.exe word_training/improve.py --run bot-temporal-v3 --initial bot-binary-v3/checkpoints/best.pt --temporal
```

Временные блоки при создании сохраняют исходные предсказания ровно, затем
учатся учитывать порядок звуков и продолжение слова. Они экспортируются
внутрь ONNX, дополнительная модель при обнаружении не нужна. Для продолжения
или экспорта такого запуска сохраняйте `--temporal`. Любые новые модели
передавайте в `choose.py --extra`; выбор по validation предшествует тесту.

Для отдельной подготовки данных добавьте `--prepare-only`, затем запустите
обучение с `--resume`. `--seed-run bot-v1` переиспользует совместимые исходные
озвучки и копирует отрицательные примеры; предыдущий запуск сохраняется.

Все данные, признаки, checkpoints и журнал состояния остаются в игнорируемой
папке `word_training/runs/bot-v2`. Рабочий результат —
`word_training/runs/bot-v2-output/wake-model.zip`, только модель и frontend.
Для проверки распакуйте этот ZIP и выполните:

```powershell
.runtime/voice/Scripts/python.exe word_training/detect.py PATH_TO_MODEL recording.wav
```

WAV: mono PCM16, 16 kHz. Проверяется всё аудио скользящими окнами по две секунды.
Промежуточное срабатывание подтверждается после 300 мс следующего контекста:
это снижает риск принять обрезанное начало «боту» за целое слово «бот».
Последний полный фрагмент проверяется и при окончании файла.
FPR тестовых окон не означает число ложных срабатываний в час такого прослушивания.
Исходный Kaggle-архив с прежней разметкой изолированного слова для этого режима
не используется как готовая модель.
