# Локальное обучение одного слова

Модель обнаруживает целое слово **«бот» в любой фразе**. «Бот, включи музыку» —
положительный пример; «робот», «боту», «кот», «борт», речь без слова и шум — отрицательные.
Модель выдаёт вероятность/факт обнаружения, не текст, команды или намерения.

Обучение использует локальную CUDA GPU, Silero v4/v5.5, четыре русских Piper-голоса
и MMS. Пунктуация/просодия варьируются у обоих классов. Добавляются независимые
pitch, темп, шум, реверберация, громкость и реальные негативные Speech Commands.
Голоса train/validation/calibration/test разделены; слово при аугментации не обрезается.
В рецепте v2 половина положительных примеров содержит только слово, половина —
слово в короткой фразе. Всего 29 850 окон, из них 19 416 используются для обучения.

Whisper Tiny encoder дообучает все четыре слоя и бинарную голову. AMP, EMA,
баланс классов/движков и поиск сложных примеров используют только train.
Validation выбирает checkpoint/FP32 или INT8; calibration фиксирует порог.
Test не используется для подбора порога. Цель — максимальный recall при FPR
не выше 0,5% отрицательных окон; качество на реальных пользователях определяется
отдельной проверкой. 90% не считаются достигнутыми до получения результатов.

Из корня проекта, в уже подготовленном Python-окружении:

```powershell
$env:PYTHONIOENCODING='utf-8'
.runtime/voice/Scripts/python.exe word_training/train.py --word бот --run bot-v2
```

Продолжить прерванный запуск с тем же рецептом: добавить `--resume`.
Для другого слова/рецепта задайте новое имя `--run`; исходники и метки проверяют
границы слова. Русские похожие отрицательные слова находятся в `data.py`.

После завершения запуска можно сравнить шаг обучения на тех же данных:

```powershell
.runtime/voice/Scripts/python.exe word_training/compare.py --run bot-v2 --comparison learning-rate
```

Сравнение сохраняет первоначальный результат и выбирает одну модель на validation.
Результаты выполненного локального обучения приведены в [RESULTS.md](RESULTS.md).

Следующее улучшение на тех же русских проверочных записях:

```powershell
.runtime/voice/Scripts/python.exe word_training/expand_voices.py --source bot-v2 --run bot-data-v3
.runtime/voice/Scripts/python.exe word_training/improve.py --source bot-data-v3 --run bot-binary-v3
```

В `bot-data-v3` добавлены восемь британских голосов Kokoro, 8000 примеров
«bot» с близким произношением и 8000 похожих отрицательных слов. Это добавочные
акустические варианты целевого слова; русский тест и его метки не меняются.
Данные содержат 45 850 окон, train — 35 416. Упакованные аудио и признаки
читаются по индексам, без создания дополнительных десятков тысяч файлов.
`improve.py` начинает с лучших весов v2, добавляет частотную аугментацию и
сохраняет исходный результат. Прерванное обучение восстанавливается с `--resume`.

Отдельные экспериментальные способы, не заменяющие выбранную модель автоматически:

```powershell
.runtime/voice/Scripts/python.exe word_training/teacher_phonetic.py --source bot-data-v3 --run bot-phonetic-tiny-v3
.runtime/voice/Scripts/python.exe word_training/train_phonetic.py --source bot-data-v3 --run bot-phonetic-tiny-v3 --backbone tiny
.runtime/voice/Scripts/python.exe word_training/acoustic_teacher.py --source bot-data-v3 --run bot-large-acoustic-v3
```

Русская модель `jonatasgrosman/wav2vec2-large-xlsr-53-russian`, revision
`ab9492f472b7de03e79117b4187ed7bf385af3e1`, хранится локально в
`.runtime/wake-phonetic-teacher`. Фонетический студент обучается на разметке
звуков «б», «о», «т», границы и других звуков. Конечный автомат CTC внутри
ONNX отвергает последовательности, принадлежащие более длинному слову.
Акустический teacher использует замороженный энкодер и обучаемую бинарную голову;
его текстовый словарь и текстовые ответы не используются. Его кэш мягких
ответов содержит только train. Для дистилляции в компактный бинарный студент:

```powershell
.runtime/voice/Scripts/python.exe word_training/improve.py --run bot-distilled-v3 --teacher bot-large-acoustic-v3
```

Это имеет смысл только после проверки качества teacher на validation.
Команды обучения на одной GPU выполняйте последовательно. `choose.py` сравнивает
завершённые v2/v3 модели и комбинации на validation, фиксирует модель, затем
калибрует порог и открывает test. Добавочный бинарный студент передаётся через
`--extra bot-distilled-v3`. Итоговый ZIP содержит только runtime.

Дополнительные три украинских голоса Piper используются как фонетические
прокси кириллического «бот», с явной меткой языка `uk` и балансировкой вместе
с русским целевым словом. Неподдерживаемые буквенные тексты исключаются: TTS
не должен превратить отрицательное «боты» в положительное «бот», отбросив букву.

```powershell
.runtime/voice/Scripts/python.exe word_training/expand_slavic.py
.runtime/voice/Scripts/python.exe word_training/improve.py --source bot-data-v4 --run bot-binary-v4 --initial bot-binary-v3/checkpoints/best.pt
```

Небольшая дополнительная временная свёртка перед объединением признаков слова:

```powershell
.runtime/voice/Scripts/python.exe word_training/improve.py --run bot-temporal-v3 --initial bot-binary-v3/checkpoints/best.pt --temporal
```

Временные блоки при создании сохраняют исходные предсказания ровно, затем
учатся учитывать порядок звуков и продолжение слова. Они экспортируются
внутрь ONNX, дополнительная модель при обнаружении не нужна. Для продолжения
или экспорта такого запуска сохраняйте `--temporal`. Любые новые модели
передавайте в `choose.py --extra`; выбор по validation предшествует тесту.

Для отдельной подготовки данных добавьте `--prepare-only`, затем запустите
обучение с `--resume`. `--seed-run bot-v1` переиспользует совместимые исходные
озвучки и копирует отрицательные примеры; предыдущий запуск сохраняется.

Все данные, признаки, checkpoints и журнал состояния остаются в игнорируемой
папке `word_training/runs/bot-v2`. Рабочий результат —
`word_training/runs/bot-v2-output/wake-model.zip`, только модель и frontend.
Для проверки распакуйте этот ZIP и выполните:

```powershell
.runtime/voice/Scripts/python.exe word_training/detect.py PATH_TO_MODEL recording.wav
```

WAV: mono PCM16, 16 kHz. Проверяется всё аудио скользящими окнами по две секунды.
Промежуточное срабатывание подтверждается после 300 мс следующего контекста:
это снижает риск принять обрезанное начало «боту» за целое слово «бот».
Последний полный фрагмент проверяется и при окончании файла.
FPR тестовых окон не означает число ложных срабатываний в час такого прослушивания.
Исходный Kaggle-архив с прежней разметкой изолированного слова для этого режима
не используется как готовая модель.
