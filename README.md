# muz-bot-ds

Discord-бот для воспроизведения YouTube и YouTube Music. Поиск, метаданные и аудио обрабатывает `yt-dlp`; звук кодируется FFmpeg и передаётся через `@discordjs/voice` с поддержкой DAVE.

## Требования

- Node.js 24.17+ и npm.
- Python 3.11+ с `venv` и `pip` на Windows или Linux.
- Доступ к PyPI при первом запуске: бот создаёт `.runtime/yt-dlp` и устанавливает `yt-dlp[default]` вместе с EJS. Последующие запуски не обновляют пакет автоматически.
- FFmpeg с `libopus`. `ffmpeg-static` устанавливает его через npm; при необходимости задайте `FFMPEG_PATH`.

Для Windows не нужны Visual Studio или нативный `@discordjs/opus`: используется `opusscript`.

## Установка и запуск

```bash
npm install
cp .env.example .env
npm run build
npm run deploy
npm start
```

На Windows вместо `cp` используйте `Copy-Item .env.example .env`. Укажите в `.env` `DISCORD_TOKEN` и `CLIENT_ID`. Необязательный `GUILD_ID` регистрирует команды сразу на тестовом сервере; без него команды регистрируются глобально. После изменения описания слэш-команд снова запустите `npm run deploy`.

На Windows после установки зависимостей запускайте `start-bot.bat` двойным щелчком. Он собирает текущий код, запускает бота в фоне и проверяет вход в Discord; повторный запуск не создаёт вторую копию. `stop-bot.bat` выключает бота вместе с его дочерними Python, yt-dlp и FFmpeg. Скрипты используют свою папку проекта, поэтому работают независимо от текущего каталога. Логи находятся в `.runtime/bot.stdout.log` и `.runtime/bot.stderr.log`, предыдущие логи сохраняются с окончанием `.previous`. Для обновления работающего бота сначала выключите его, затем запустите снова. Текущая очередь после выключения не сохраняется.

`npm run dev` запускает исходники TypeScript в режиме наблюдения. `npm run update:ytdlp` обновляет управляемую установку `yt-dlp`. При использовании `YT_DLP_PATH` бот проверяет внешний исполняемый файл, но его обновление остаётся за администратором.

## Команды

| Команда | Действие |
| --- | --- |
| `/join` | Войти в ваш голосовой канал и включить прослушивание без запуска музыки. |
| `/play <query> [infinite]` | Добавить видео, поиск или плейлист. Без `infinite` из плейлиста берётся первый трек; с ним — до 25. |
| `/skip`, `/stop`, `/pause`, `/resume` | Управлять воспроизведением. |
| `/clear`, `/volume <1-150>`, `/autoplay` | Управлять очередью, громкостью и рекомендациями. |
| `/queue [page]`, `/nowplaying` | Посмотреть состояние. |
| `/player` | Показать публичный плеер с кнопками. |
| `/watch` | Создать приглашение в Watch Together. |
| `/voice on`, `/voice off`, `/voice status` | Включить, отключить или проверить голосовое управление. |
| `/voice name [value]` | Сохранить новое обращение на этом сервере; без `value` — вернуть имя Discord. |

Если ссылка из «Понравившейся музыки» содержит `v=`, `/play` воспроизводит это видео как обычный трек. Ссылка только с `list=LM` не содержит ID песни; для неё укажите ссылку на конкретную песню или её название.

Команды и кнопки, меняющие воспроизведение, доступны участникам того же голосового канала, что и бот. Ответы команд приватные, кроме публичного сообщения `/player` и его автоматического обновления. Бот выходит из голосового канала через пять минут без музыки, в том числе после `/join` с пустой очередью.

## Голосовое управление

Подготовьте локальные модели командой `npm run setup:voice`, затем выполните `npm run deploy` и запустите бота. Установка требует Python 3.11+, доступа к PyPI, PyTorch и Hugging Face, места для зависимостей и моделей. Окружение, веса и закреплённый список установленных зависимостей находятся в `.runtime/voice`. Whisper `small` работает через faster-whisper на CPU в INT8, Laya Multilingual выбирает действие по русскому тексту. Модели загружаются один раз в постоянный процесс; после подготовки обработка работает без облачного API. Повторная `setup:voice` переустанавливает закреплённые зависимости и проверяет модели; обновления при обычном запуске не скачиваются.

Для дообученной Laya распакуйте checkpoint в `.runtime/voice/models/` и задайте в `.env` путь `LAYA_MODEL_PATH=.runtime/voice/models/laya-muz-bot-v3`. В каталоге нужны `model.safetensors`, `rl_agent_config.json`, `encoder/config.json` и токенизатор в `tokenizer/`. Путь разрешается относительно проекта; изменение применяется после перезапуска. При указанном локальном пути веса из Hugging Face не загружаются. Чтобы вернуться к базовой модели из подготовленного кэша, удалите `LAYA_MODEL_PATH`. В начале лога выводится имя реально загруженного checkpoint. Отсутствующий или несовместимый checkpoint отключает голосовой обработчик; `/play` продолжает работать.

Профиль `laya-muz-bot-ds-v3` получает подготовленный TypeScript запрос и состояние плеера с `phase: request`, затем настоящие результаты поиска с `phase: tool_result`. Перед окончательным выбором проверяется версия кандидатов; в `phase: rerank` сохраняются их исходные метки `c0…c4`. Схема адаптера находится в `scripts/laya_music_v3.json`: варианты взяты из описанного контракта v3, формулировки вопросов проверены на checkpoint. Это не копия обучающего генератора или воспроизведение его hard-test. Веса и отчёты хранятся в игнорируемой `.runtime/`; дополнительное обучение не выполняется. Slash-команды при замене модели регистрировать заново не требуется.

Чтобы начать без музыки, войдите в голосовой канал и выполните `/join`. Бот подключится к вашему каналу и включит прослушивание. Повторный `/join` в том же канале снова включает его после `/voice off`, сохраняя текущую музыку и очередь. Если локальные модели недоступны или бот занят в другом канале, команда сообщит об этом приватно.

После подключения бот автоматически слушает обращение по своему серверному нику, либо имени аккаунта. Имя произносится отдельной фразой: **«Муза» → дождаться сигнала → «Следующий трек»**. Нужное обращение показывает `/voice status`. Чтобы изменить его, используйте `/voice name value:Джев`; имя сохраняется отдельно для каждого сервера и переживает перезапуск. `/voice name` без значения сбрасывает настройку. Менять её и включать/выключать прослушивание может участник канала бота.

На каждый новый запрос снова назовите имя и дождитесь сигнала. Для возобновления текущего трека на паузе подходят «продолжай», «продолжай музыку», «продолжи музыку», «возобнови», «включи», «включи музыку» и «включи обратно». Без текущего трека на паузе команда «включи» без названия не запускает музыку.

Для заказа песни произнесите **«Муза» → сигнал → «включи Numb»**, «поставь песню Rammstein Sonne», «сыграй Numb live» или «воспроизведи Numb remix». Laya получает `{ message, selected_track: null }` и выбирает способ обработки; название извлекает TypeScript. Поиск `ytsearch5` возвращает до пяти корректных уникальных кандидатов. Обычный запрос запускает первый результат, а уточнения live/концертная, remix/ремикс, cover/кавер, acoustic/акустическая, instrumental/инструментальная позволяют Laya выбрать нужную версию по названию, исполнителю/каналу и длительности. Сначала Laya определяет версии кандидатов, затем при нескольких подходящих сравнивает их с запросом. Выбор применяется при уверенности от 0,6; иначе используется первый кандидат.

Голосовой заказ добавляет один трек в обычную очередь, сохраняя текущую музыку и приоритет перед рекомендациями. При пустой очереди он начинает играть сразу. Распознанная прямая ссылка YouTube или YouTube Music с идентификатором видео обрабатывается без поиска; параметр плейлиста не добавляет другие треки. Бот должен уже находиться в голосовом канале и слушать обращение. `/play` сохраняет прежний поиск одного результата; обычные сообщения чата не обрабатываются. «Включи эту» и выбор из списка пока не поддерживаются.

Если решение Laya завершилось ошибкой после распознавания речи, однозначный заказ ищется и получает первый результат. Ошибка или слабая уверенность повторного выбора также оставляет первый результат. Явный отказ модели (`unknown`) или слабая уверенность маршрутизации не запускают песню. В v3 уверенные `no_result` и `best_track: none` также завершают заказ без изменения очереди. Обычное название сохраняет первый результат, даже если модель предлагает дополнительное сравнение; сравнение применяется к явному уточнению версии. Если недоступен весь обработчик Whisper + Laya, новые голосовые заказы не распознаются; уже распознанный заказ может завершиться через fallback. Уход говорящего из канала, `/voice off`, остановка бота или смена подключения отменяют незавершённый заказ. Ошибка поиска или пустая выдача не изменяют очередь.

После имени достаточно 400 мс тишины. Для короткого обращения «Бот» Whisper получает словарь с именем и созвучными словами; для остальных имён дополнительного словаря нет. Фрагменты с низкой уверенностью или высокой вероятностью отсутствия речи отбрасываются. Новое обращение принимается и во время распознавания предыдущего. Whisper обрабатывает фактическую длину короткой записи с запасом контекста вместо дополнения до 30 секунд, а модели прогреваются при запуске. Модель остаётся `small`; для самой команды ожидание тишины сохраняется на уровне 800 мс.

После сигнала музыка становится на 80% тише. У назвавшего имя человека есть 10 секунд на начало команды; речь завершается после 800 мс тишины, максимальная длительность — 15 секунд. Другие участники не могут перехватить команду. После выполнения, молчания или ошибки приглушение снимается. Изменённая громкость сохраняется; пауза и остановка остаются в силе. На время самого короткого сигнала музыкальный ресурс приостанавливается и затем продолжается с прежнего места.

Доступны «следующий трек», «пауза», «продолжи музыку», «останови музыку» (с выходом из канала), «громкость пятьдесят процентов», «сделай громче» и «сделай тише», а также заказ песни по явному названию. Относительное изменение — 10 процентных пунктов, диапазон — 1–150%. За одно обращение принимается одно действие. Отрицательные, составные и непонятные просьбы не выполняются; союз внутри названия песни сохраняется. Обращение должно совпадать с результатом распознавания целиком. Эквивалентное написание латиницей принимается (`Bot` для «Бот»); похожие слова вроде «Вот» и «Кот» не активируют бота.

Для отслеживания имени речь участников обрабатывается локально ещё до сигнала. Аудио и расшифровки находятся в памяти, не сохраняются и не выводятся в обычные логи. `/voice off` выключает приём до следующего подключения; новое подключение вновь включает его автоматически. Если модели не подготовлены или обработчик остановлен, музыкальные команды продолжают работать; восстановить прослушивание можно через `/voice on`.

Качество Whisper и Laya зависит от голоса, шума и формулировок. Порог уверенности служит фильтром, а не гарантией точности. Перед использованием проверьте своё имя и команды в тестовом голосовом канале.

Для диагностики задайте `VOICE_DEBUG=1` и перезапустите бота. Записи `[Voice:…]` показывают время распознавания, число слов, выбранное Laya действие и уверенность, действие после проверки кодом и результат изменения плеера. `audioMs`, `rms` и `peak` показывают длительность и уровень декодированного звука; `vadMs`, `segments` и `rejectedSegments` — сколько речи обнаружено и отфильтровано Whisper. `wakeDistance` — число отличающихся символов от имени после нормализации; это только диагностика, похожее слово не активирует бота. Для заказов музыки добавлены этапы `routing`, `search`, `selection`, `fallback`, количество кандидатов, индекс выбора и причина fallback. `modelAction: "unknown"` означает отказ модели; `action: "unknown"` — команда не выполнена; `changed: false` — метод плеера не изменил состояние. Аудио, текст речи и идентификаторы говорящих в эту диагностику не входят. По умолчанию она выключена.

## Проверка

`npm test` запускает автономные тесты и сборку. `npm run test:integration` отдельно проверяет YouTube, получение аудио и рекомендации; для него нужны сеть, Python, yt-dlp и FFmpeg. Для окончательной проверки запустите бота на тестовом сервере и проверьте `/play`, `/player`, кнопки, пропуск и повторное подключение.

`python tests/music_worker_test.py` проверяет Python-контракт маршрутизации и выбора кандидатов автономно, без установки моделей.

`npm run test:voice` отдельно проверяет настоящую Laya на русских командах, маршрутизации музыкальных заказов и выборе версий из кандидатов, печатает решения, уверенность и задержку. Для проверки Whisper задайте `VOICE_TEST_FIXTURES` — путь к локальному JSON-манифесту, например `[{"file":"wake.wav","wakeName":"Муза"},{"file":"next.wav","action":"skip"}]`. Для заказа музыки используйте `{ "file": "song.wav", "musicQuery": "Numb live" }`: проверяются извлечённый запрос и маршрутизация без настоящего поиска. WAV-пути разрешаются относительно манифеста; звук декодируется FFmpeg в памяти, расшифровки не печатаются. Синтезированная речь проверяет работоспособность цепочки, но не заменяет проверку настоящих голосов в Discord. `npm run test:integration` дополнительно проверяет выдачу нескольких кандидатов YouTube.

## Настройки

| Переменная | Назначение |
| --- | --- |
| `DISCORD_TOKEN` | Токен бота. |
| `CLIENT_ID` | ID приложения. |
| `GUILD_ID` | Сервер для мгновенной регистрации команд. |
| `YT_DLP_PATH` | Внешний yt-dlp вместо управляемого Python-окружения. |
| `FFMPEG_PATH` | Внешний FFmpeg вместо `ffmpeg-static`. |
| `WATCH_TOGETHER_APP_ID` | ID активности Watch Together. |
| `WHISPER_MODEL` | Модель Whisper при `setup:voice`; по умолчанию `small`, нужна многоязычная версия. |
| `VOICE_CPU_THREADS` | Число потоков CPU для локальных моделей, по умолчанию 4, максимум 8. |
| `LAYA_MODEL_PATH` | Каталог локальной дообученной Laya; относительный путь считается от корня проекта. |
| `VOICE_TEST_FIXTURES` | Манифест локальных аудиопримеров для `test:voice`. |
| `VOICE_DEBUG` | `1` включает диагностику решений и состояния плеера без записи речи. |

Боту нужны Gateway Intents `Guilds` и `GuildVoiceStates`, а также права `Connect`, `Speak`, `Send Messages` и `Embed Links`. Для `/watch` дополнительно нужны `Create Invite` и `Use Activities`.
