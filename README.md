# muz-bot-ds

Discord-бот для воспроизведения YouTube, YouTube Music и радио. Поиск, метаданные и аудио YouTube обрабатывает `yt-dlp`; радиопотоки открываются непосредственно в FFmpeg. Звук передаётся через `@discordjs/voice` с поддержкой DAVE.

Текстовые и голосовые заказы ищут только в разделе «Песни» YouTube Music. Если песня не найдена, бот не подставляет результат обычного видеопоиска. В бесконечном режиме кандидаты из радио YouTube проходят дополнительную проверку музыкальных метаданных; подкасты, интервью, лекции, аудиокниги, целые альбомы и текущие трансляции пропускаются. Видео без подтверждения музыкального содержимого не добавляются в автоподбор.

Для выбранной песни бот запрашивает полные метаданные, если сокращённый поиск не вернул длительность. Плеер показывает прошедшее и полное время записи. Надпись «Прямой эфир» появляется только при подтверждённом статусе текущей трансляции; отсутствие длительности само по себе не означает эфир.

## Требования

- Node.js 24.17+ и npm.
- Python 3.11+ с `venv` и `pip` на Windows или Linux.
- Доступ к PyPI при первом запуске: бот создаёт `.runtime/yt-dlp` и устанавливает `yt-dlp[default]` вместе с EJS. Последующие запуски не обновляют пакет автоматически.
- FFmpeg с `libopus`. `ffmpeg-static` устанавливает его через npm; при необходимости задайте `FFMPEG_PATH`.

Для Windows не нужны Visual Studio или нативный `@discordjs/opus`: используется `opusscript`.

## Установка и запуск

На Windows запустите `setup-bot.bat`: выберите лёгкий или тяжёлый профиль. Установщик проверяет Node.js 24.17+ и Python 3.11+, устанавливает недостающие программы через WinGet, затем устанавливает npm-зависимости и FFmpeg, подготавливает голос, готовые ответы и yt-dlp, собирает бота и регистрирует команды Discord. Если реквизиты ещё не заданы, он запросит токен (ввод скрыт) и ID приложения. Существующий `.env` сохраняется, изменяются только выбранный профиль и настройки TTS. Работающий бот перед установкой останавливается. Для проверки без изменений: `setup-bot.bat -CheckOnly`. Параметры `-Profile light`, `-Profile heavy -Device cuda` и `-NoDeploy` позволяют пропустить меню или регистрацию. Если WinGet отсутствует, установщик покажет ссылку на Microsoft App Installer. Первый запуск требует интернета; бот запускается отдельно через `start-bot.bat`.

Для ручной установки на Windows или Linux:

```bash
npm install
cp .env.example .env
npm run build
npm run setup:voice
npm run setup:tts
npm run deploy
npm start
```

На Windows вместо `cp` используйте `Copy-Item .env.example .env`. Укажите в `.env` `DISCORD_TOKEN` и `CLIENT_ID`. Необязательный `GUILD_ID` регистрирует команды сразу на тестовом сервере; без него команды регистрируются глобально. После изменения описания слэш-команд снова запустите `npm run deploy`.

На Windows после установки зависимостей запускайте `start-bot.bat` двойным щелчком. Он собирает текущий код, запускает бота в фоне и проверяет вход в Discord; повторный запуск не создаёт вторую копию. `stop-bot.bat` выключает бота вместе с его дочерними Python, yt-dlp и FFmpeg. Скрипты используют свою папку проекта, поэтому работают независимо от текущего каталога. Логи находятся в `.runtime/bot.stdout.log` и `.runtime/bot.stderr.log`, предыдущие логи сохраняются с окончанием `.previous`. Для обновления работающего бота сначала выключите его, затем запустите снова. Текущая очередь после выключения не сохраняется.

`npm run dev` запускает исходники TypeScript в режиме наблюдения. `npm run update:ytdlp` обновляет управляемую установку `yt-dlp`. При использовании `YT_DLP_PATH` бот проверяет внешний исполняемый файл, но его обновление остаётся за администратором.

## Команды

| Команда | Действие |
| --- | --- |
| `/join` | Войти в ваш голосовой канал и включить прослушивание без запуска музыки. |
| `/play <query> [infinite]` | Добавить песню, ссылку или плейлист либо включить известную радиостанцию. Без `infinite` из плейлиста берётся первый трек; с ним — до 25. |
| `/radio <station>` | Включить радиостанцию; названия доступны в автодополнении. |
| `/skip`, `/stop`, `/pause`, `/resume` | Управлять воспроизведением. |
| `/clear`, `/volume <1-150>`, `/autoplay` | Управлять очередью, громкостью и рекомендациями. |
| `/speed <value>` | Скорость 0.5–2× с изменением тональности; `1` возвращает обычное звучание. |
| `/queue [page]`, `/nowplaying` | Посмотреть состояние. |
| `/player` | Показать публичный плеер с кнопками. |
| `/watch` | Создать приглашение в Watch Together. |
| `/voice on`, `/voice off`, `/voice status` | Включить, отключить или проверить голосовое управление. |
| `/voice name [value]` | Сохранить новое обращение на этом сервере; без `value` — вернуть имя Discord. |

Если ссылка из «Понравившейся музыки» содержит `v=`, `/play` воспроизводит это видео как обычный трек. Ссылка только с `list=LM` не содержит ID песни; для неё укажите ссылку на конкретную песню или её название.

Команды и кнопки, меняющие воспроизведение, доступны участникам того же голосового канала, что и бот. Ответы команд приватные, кроме публичного сообщения `/player` и его автоматического обновления. Бот выходит из голосового канала через пять минут без музыки, в том числе после `/join` с пустой очередью.

`/speed value:0.8` замедляет музыку и делает голос ниже, `/speed value:1.25` ускоряет и делает голос выше, `/speed value:1` возвращает обычное звучание. Настройка действует на текущую песню и следующие треки этой очереди, включая рекомендации и повтор. При смене скорости текущий трек загружается заново с сохранением позиции и паузы; возможна задержка буферизации, особенно в конце длинной записи. После остановки очереди новая очередь начинает с 1×. Изменение скорости доступно только через `/speed`; выбранное значение видно в `/player` и `/nowplaying`.

## Радио

Поддерживаются Европа Плюс, Ретро FM, Дорожное радио, Русское радио, Авторадио, DFM, Радио ENERGY, Love Radio, Радио Дача и Наше радио. Используется основной российский эфир. `/radio station:Retro FM` и `/play query:включи Европа Плюс` подключают бота к голосовому каналу вызвавшего команду пользователя. При уже подключённом боте необходимо находиться в том же канале.

Для голосовой команды произнесите имя бота, дождитесь сигнала, затем скажите «включи Европа Плюс», «поставь Retro FM» или только название станции. Поддерживаются русские и латинские алиасы. Каталог разбирается до поиска YouTube и решения Laya. В проверке checkpoint `laya-muz-bot-controls-v4` экспериментальный выбор радио был правильным лишь в 3 из 8 запросов; штатный классификатор отдельного действия радио не имеет. Радио поэтому определяется правилами каталога; переобучение не выполнялось.

Вопросы, отрицания и составные радиокоманды отклоняются. Для песни с похожим названием скажите «включи песню …»; `Radio Ga Ga` сохраняет обычный поиск музыки. Неизвестная станция в `/radio` или после «включи радио …» сообщает об отсутствии поддержки. Обычные сообщения Discord не запускают команды.

После получения первых аудиоданных эфир заменяет текущую музыку, очищает очередь и выключает повтор и автоподбор. Если поток не открывается, музыка и очередь сохраняются. Новый запрос отменяет ожидающее переключение. Громкость, приглушение при обращении, пауза и остановка доступны; после паузы возобновляется текущий эфир. Скорость эфира равна 1×, повтор и автоподбор недоступны. Заказ песни переключает радио на музыку; `/skip` завершает эфир и запускает ожидающие треки, если они есть.

При обрыве выполняются три попытки подключения через 1, 2 и 4 секунды. После неудачи бот переходит к очереди либо ожиданию с выходом через пять минут. В плеере, текущем воспроизведении и очереди отображаются станция, «Прямой эфир» и ссылка на официальный сайт. Потоки проходят ту же нормализацию и Opus-кодирование; проверка сертификатов TLS включена.

## Громкость и качество звука

Каждый трек автоматически проходит потоковую нормализацию FFmpeg `loudnorm`: цель −16 LUFS, диапазон громкости 11 LU и максимум −4 dBTP. Запас по пикам учитывает `/volume 150`. `/volume`, приглушение после обращения и плавный пропуск работают поверх нормализованного звука. Однопроходный фильтр адаптируется по мере поступления музыки; он уменьшает различия между треками, но не гарантирует одинаковую громкость каждого фрагмента. Начало воспроизведения может немного задерживаться из-за анализа первых секунд.

`yt-dlp` выбирает лучший доступный аудиоформат без ограничения WebM. FFmpeg выдаёт стерео PCM 48 кГц; после регулировки громкости звук кодируется в Opus 128 кбит/с один раз. Промежуточное кодирование и декодирование Opus исключены. Сохраняется `opusscript`, поэтому Visual Studio не требуется. Плохую исходную запись или уже потерянные при загрузке детали восстановить этой обработкой нельзя.

Для локального файла доступен отдельный скрипт с двумя проходами: сначала измерение всей записи, затем нормализация с теми же целями. По возможности применяется постоянное усиление, сохраняющее музыкальную динамику; если пики или диапазон не позволяют, FFmpeg использует динамический режим. Результат сохраняется в FLAC или WAV без дополнительного сжатия с потерями; существующие файлы не перезаписываются.

```bash
npm run normalize:audio -- "input.mp3" "output.flac"
```

Фильтры описаны в документации FFmpeg: [нормализация громкости](https://ffmpeg.org/ffmpeg-filters.html#loudnorm) и [изменение скорости и тональности](https://ffmpeg.org/ffmpeg-filters.html#asetrate). Нужен FFmpeg с `loudnorm`, `aresample`, `aeval`, `asetrate`, `atrim`, `asetpts` и `libopus`; доступность проверяется при запуске.

## Голосовое управление

Команды «включи/выключи бесконечный режим», «включи/выключи автоплей» и «включи/выключи рекомендации» управляют автоподбором YouTube после ручной очереди. «Включи/выключи повтор трека» управляет повтором текущей песни. Эти режимы взаимоисключающие; повторное включение не выключает уже активный режим. «Очисти очередь» удаляет ожидающие треки, сохраняя текущую песню. «Выключи голосовое управление» прекращает прослушивание; снова включить его можно через `/voice on` или `/join`. Явные команды режимов разбираются до поиска и не зависят от классификации Laya. Неизвестные, отрицательные и составные команды режимов отклоняются. Названия песен с такими словами остаются доступны через «включи песню …».

По умолчанию `VOICE_PROFILE=light`: одна многоязычная Whisper `small` распознаёт и обращение, и команду на CPU в INT8. Действия выбираются правилами TypeScript; PyTorch, Transformers и Laya в лёгкое окружение не устанавливаются. Его зависимости и манифест находятся в `.runtime/voice-light`. Для ещё меньшей модели задайте `WHISPER_LIGHT_MODEL=base` или `tiny`, затем выполните `npm run setup:voice -- --models-only`; их точность отдельно не проверена. Названия моделей читаются при подготовке, при запуске используется проверенный манифест.

`VOICE_PROFILE=heavy` сохраняет прежний вариант: Whisper `large-v3-turbo` для команд, `small` для обращения и Laya для управления плеером. Его окружение остаётся в `.runtime/voice`; имеющиеся модели и `LAYA_MODEL_PATH` сохраняются при выборе лёгкого профиля. Для NVIDIA задайте `VOICE_DEVICE=cuda`, для CPU — `cpu`, затем выполните `npm run setup:voice`. CUDA использует PyTorch CUDA 12.8 и требует совместимого драйвера и свободной видеопамяти. `WHISPER_MODEL` и `WHISPER_WAKE_MODEL` относятся только к тяжёлому профилю; старые манифесты продолжают работать. Подготовленные веса Whisper общие для обоих окружений, повторное скачивание одинаковой модели не нужно.

Бот входит в Discord без загрузки голосовых моделей. Они загружаются при `/join`, `/voice on` или подключении для воспроизведения; запуск музыки не ждёт их загрузки. Один процесс обслуживает все слушающие серверы. Через 60 секунд после отключения последнего прослушивания или выхода бота он завершается и освобождает память; активное распознавание сначала заканчивается. Пока прослушивание включено, Whisper остаётся загруженной, чтобы слышать имя. `/voice status` показывает профиль и состояние подготовки/загрузки. Повторное включение загружает модели снова.

Для смены профиля задайте `VOICE_PROFILE=light` или `heavy`, подготовьте выбранный профиль через `npm run setup:voice` и перезапустите бота, либо повторно запустите установщик. Первый раз нужны PyPI и Hugging Face; после подготовки распознавание работает локально без облачного API. При обычном запуске голосовые зависимости не обновляются. `npm run setup:voice -- --models-only` обновляет только модели. Манифест публикуется после успешного прогрева; названия реально загруженных моделей выводятся в лог. При смене только моделей регистрация slash-команд не нужна.

Для дообученной Laya распакуйте checkpoint в `.runtime/voice/models/` и задайте в `.env` путь `LAYA_MODEL_PATH=.runtime/voice/models/laya-muz-bot-v3`. В каталоге нужны `model.safetensors`, `rl_agent_config.json`, `encoder/config.json` и токенизатор в `tokenizer/`. Путь разрешается относительно проекта; изменение применяется после перезапуска. При указанном локальном пути веса из Hugging Face не загружаются. Чтобы вернуться к базовой модели из подготовленного кэша, удалите `LAYA_MODEL_PATH`. В начале лога выводится имя реально загруженного checkpoint. Отсутствующий или несовместимый checkpoint отключает голосовой обработчик; `/play` продолжает работать.

Следующий запуск **Action V4** с явно составленной синтетикой, встроенными данными и проверкой восстановления описан в [инструкции по обучению](notebooks/README.md). Он учит оба вопроса действующего классификатора вместе, проверяет TypeScript-правила, отдельно калибрует уверенность и проверяет сохранённый checkpoint. [Первоначальный ноутбук Google Colab/Kaggle](notebooks/laya_training_colab_kaggle.ipynb) сохраняется для ручного корпуса. Дополнительная схема «реагировать / выбрать функцию / intent» требует отдельного корпуса с контекстом голосовой сессии и пока не вызывается ботом.

В лёгком профиле команды управления определяют правила TypeScript, в тяжёлом — Laya с проверкой допустимости. Явные поисковые запросы («включи Монеточку») и прямые ссылки обрабатывает TypeScript без решения Laya: название или имя исполнителя не обязаны быть знакомы модели. Названия без команды сначала проходят проверку управления; выполнить действие можно только при наличии соответствующих слов и допустимой уверенности. Затем название становится поисковым запросом. Всегда берётся первый корректный кандидат в порядке YouTube, включая запросы live, remix и cover. Старый обученный контракт маршрутизации и выбора кандидатов сохраняется в адаптере `scripts/laya_music_v3.json` для проверки checkpoint, но обработчик заказа его не вызывает. Это не копия обучающего генератора или воспроизведение его hard-test. Веса и отчёты хранятся в игнорируемой `.runtime/`; дополнительное обучение не выполняется. Slash-команды при замене модели регистрировать заново не требуется.

Чтобы начать без музыки, войдите в голосовой канал и выполните `/join`. Бот подключится к вашему каналу и включит прослушивание. Повторный `/join` в том же канале снова включает его после `/voice off`, сохраняя текущую музыку и очередь. Если локальные модели недоступны или бот занят в другом канале, команда сообщит об этом приватно.

После подключения бот автоматически слушает обращение по своему серверному нику, либо имени аккаунта. Имя произносится отдельной фразой: **«Муза» → дождаться сигнала → «Следующий трек»**. Нужное обращение показывает `/voice status`. Чтобы изменить его, используйте `/voice name value:Джев`; имя сохраняется отдельно для каждого сервера и переживает перезапуск. `/voice name` без значения сбрасывает настройку. Менять её и включать/выключать прослушивание может участник канала бота.

На каждый новый запрос снова назовите имя и дождитесь сигнала. Для возобновления текущего трека на паузе подходят «продолжай», «продолжай музыку», «продолжи музыку», «возобнови», «включи», «включи музыку» и «включи обратно». Без текущего трека на паузе команда «включи» без названия не запускает музыку.

Короткие команды «следующее», «следующая», «далее», «дальше», «переключи», `next` и `skip` приводятся к «Следующий трек» и проходят проверку выбранного профиля. Они не становятся названиями для поиска даже при отказе модели. Аналогично поддерживаются `pause`, `resume`, `stop`, `louder` и `quieter`. Чтобы найти песню с названием Next или Pause, назовите её явно: «включи Next». Отрицательная или составная команда не выполняется.

Для заказа песни произнесите **«Муза» → сигнал → «включи Монеточку»**, «поставь песню Rammstein Sonne», «хочу послушать Земфиру», «сыграй Numb live» или «воспроизведи Numb remix». После сигнала можно назвать только исполнителя, название или описание: «Монеточка», «песни Монеточки», «песня из Лунтика». TypeScript убирает команду и передаёт остальной запрос в раздел «Песни» YouTube Music; он возвращает до пяти корректных уникальных кандидатов, запускается первая найденная песня. Исполнители не ограничены списком, склонения и уточнения сохраняются для поисковой коррекции YouTube. Уточнения live/концертная, remix/ремикс, cover/кавер, acoustic/акустическая и instrumental/инструментальная влияют на выдачу YouTube; дополнительного выбора Laya нет. Для неоднозначного названия можно уточнить исполнителя или название песни.

Допустимы короткие вводные слова «вот», «ну», «пожалуйста», «давай», формы «включить», «включай», «запусти», «проиграй» и просьба «можешь включить». Запятая после команды не мешает разбору. Потерянное при распознавании начало команды («ключи…») также обрабатывается. В заказе «включи песню из Лунтика» поисковый запрос сохраняет музыкальный смысл: `песня из Лунтика`, а не просто `из Лунтика`. Если конкретное название не указано, играет первый результат по этому описанию; для определённой песни назовите её название.

Голосовой заказ добавляет один трек в обычную очередь, сохраняя текущую музыку и приоритет перед рекомендациями. При пустой очереди он начинает играть сразу. Распознанная прямая ссылка YouTube или YouTube Music с идентификатором видео обрабатывается без поиска; параметр плейлиста не добавляет другие треки. Бот должен уже находиться в голосовом канале и слушать обращение. `/play` использует тот же раздел «Песни» и выбирает одну песню; обычные сообщения чата не обрабатываются. «Включи эту» и выбор из списка пока не поддерживаются.

Явный заказ музыки не зависит от `unknown` или уверенности Laya: поисковый запрос сразу отправляется в YouTube. Для названия без команды `unknown` или сбой классификации также допускают поиск, если текст не является командой управления. Для управления паузой, пропуском и громкостью проверки уверенности и допустимости команды сохраняются. Если недоступен обработчик распознавания речи, новые голосовые заказы не распознаются; уже распознанный заказ может завершить поиск после сбоя модели. Уход говорящего из канала, `/voice off`, остановка бота или смена подключения отменяют незавершённый заказ. Ошибка поиска или пустая выдача не изменяют очередь.

Подтверждения поставляются готовыми в `assets/tts` (женский голос `xenia`, стерео PCM 48 кГц, −18 LUFS, −6 dBTP). Короткие фразы длятся примерно 0,7–1,7 секунды, весь сжатый набор занимает около 2,3 МиБ. По умолчанию `VOICE_TTS_ENGINE=bundled`: `npm run setup:tts` копирует записи в `.runtime/tts`, ничего не синтезируя и не скачивая. Бот также может читать их прямо из `assets/tts`. Python, PyTorch и модель TTS для этого не нужны. Для своих фраз остаются `VOICE_TTS_ENGINE=silero` (нужен PyTorch из тяжёлого окружения, модель Silero скачивается с проверкой TLS) и `piper` (отдельное окружение Piper / Ирина). Измените `src/voice/confirmations.json`, подготовьте собственный кэш через выбранный движок и перезапустите бота; для режима bundled надо обновить и сами записи с манифестом. Во время работы бот хранит только готовое аудио, речь пользователя TTS не получает.

После принятого заказа звучит «Включаю», а при занятом плеере — «В очереди». Остальные ответы тоже короткие: «Пауза», «Следующий», «Громче». Музыка кратко приостанавливается на время ответа; подтверждение паузы не возобновляет её. Пропуск и выход выполняются после ответа, пока сессия актуальна. Уход говорящего, `/voice off`, смена подключения и остановка отменяют незавершённую озвучку и отложенное действие. Сбой озвучки не блокирует управление. `VOICE_TTS=0` полностью отключает ответы. Названия песен пока не произносятся; slash-команды и кнопки не озвучиваются.

После имени достаточно 400 мс тишины. Для короткого обращения «Бот» модель обращения получает словарь с именем и созвучными словами; для остальных имён дополнительного словаря нет. Фрагменты с низкой уверенностью или высокой вероятностью отсутствия речи отбрасываются. Новое обращение принимается и во время распознавания предыдущего. Модель обращения обрабатывает короткую запись с запасом контекста; модель команды сохраняет стандартное окно Whisper. Модели прогреваются при включении прослушивания. Для самой команды ожидание тишины сохраняется на уровне 800 мс.

Для команды Whisper `large-v3-turbo` сравнивает пять гипотез распознавания и автоматически определяет язык. Используется задача транскрипции, сохраняющая услышанные слова, а не перевода; поддерживаются русские, английские и смешанные запросы вроде «включи Moscow Never Sleeps». Управление плеером сохраняет русские команды Laya. Для обращения остаются русский язык и быстрый режим с одной гипотезой. Подсказка распознавания содержит примеры русских и английских названий, но не ограничивает допустимые запросы. Более крупная модель требует больше памяти и времени; фактическая задержка зависит от CPU и длины команды. При ошибке поиска звучит «Не удалось найти трек. Попробуйте ещё раз», при неподдержанной просьбе — «Не поняла команду. Назовите песню или исполнителя». После изменения набора фраз повторите `npm run setup:tts`.

После сигнала музыка становится на 80% тише. У назвавшего имя человека есть 10 секунд на начало команды; речь завершается после 800 мс тишины, максимальная длительность — 15 секунд. Другие участники не могут перехватить команду. После выполнения, молчания или ошибки приглушение снимается. Изменённая громкость сохраняется; пауза и остановка остаются в силе. На время самого короткого сигнала музыкальный ресурс приостанавливается и затем продолжается с прежнего места.

Доступны «следующий трек», «пауза», «продолжи музыку», «останови музыку» (с выходом из канала), «громкость пятьдесят процентов», «сделай громче» и «сделай тише», а также поиск по названию, исполнителю или описанию. Относительное изменение — 10 процентных пунктов, диапазон — 1–150%. За одно обращение принимается одно действие. Отрицательные и составные команды, пустой запрос и ссылки на отсутствующий контекст не выполняются; союз внутри названия песни сохраняется. Обращение должно совпадать с результатом распознавания целиком. Эквивалентное написание латиницей принимается (`Bot` для «Бот»); похожие слова вроде «Вот» и «Кот» не активируют бота.

Для отслеживания имени речь участников обрабатывается локально ещё до сигнала. Аудио и расшифровки находятся в памяти, не сохраняются и не выводятся в обычные логи. `/voice off` выключает приём до следующего подключения; новое подключение вновь включает его автоматически. Если модели не подготовлены или обработчик остановлен, музыкальные команды продолжают работать; восстановить прослушивание можно через `/voice on`.

Качество Whisper и Laya зависит от голоса, шума и формулировок. Порог уверенности служит фильтром, а не гарантией точности. Перед использованием проверьте своё имя и команды в тестовом голосовом канале.

Для диагностики задайте `VOICE_DEBUG=1` и перезапустите бота. Записи `[Voice:…]` показывают время распознавания, число слов, выбранное Laya действие и уверенность, действие после проверки кодом и результат изменения плеера. `audioMs`, `rms` и `peak` показывают длительность и уровень декодированного звука; `vadMs`, `segments` и `rejectedSegments` — сколько речи обнаружено и отфильтровано Whisper. `wakeDistance` — число отличающихся символов от имени после нормализации; это только диагностика, похожее слово не активирует бота. Для заказов музыки добавлены этапы `routing`, `search`, `rejected`, `fallback`, количество кандидатов и причины отказа или fallback. Записи `[TTS:…]` содержат ключ фиксированной фразы, статус, длительность звука, время воспроизведения и максимальную задержку цикла Node.js (`eventLoopMaxMs`); распознанная речь в них не входит. Ошибка воспроизведения подтверждения отмечается как `[TTS:…] playback failed`. `modelAction: "unknown"` означает отказ модели; `action: "unknown"` — команда не выполнена; `changed: false` — метод плеера не изменил состояние. Аудио, текст речи и идентификаторы говорящих в эту диагностику не входят. По умолчанию она выключена.

Поле `requestKind` отличает поисковый запрос (`search`), прямое видео (`video`), радио (`radio`), управление (`control`) и отказ разбора (`rejected`). Для поискового запроса нет этапа решения Laya: `routing` показывает маршрут, выбранный кодом, а `search` — число кандидатов и время поиска.

## Проверка

`npm test` запускает автономные тесты и сборку. Проверки аудио используют настоящий FFmpeg: записи с разницей 20 дБ выравниваются до общей цели, сохраняются тишина, короткие записи, стерео и высокие частоты после Opus, проверяется двухпроходный скрипт. `npm run test:integration` отдельно проверяет YouTube, нормализованный PCM, итоговые пакеты Opus после регулировки громкости и рекомендации; для него нужны сеть, Python, yt-dlp и FFmpeg. Для окончательной проверки запустите бота на тестовом сервере и проверьте `/play`, `/player`, кнопки, пропуск и повторное подключение.

`python tests/music_worker_test.py` проверяет Python-контракт маршрутизации и выбора кандидатов автономно, без установки моделей.

`npm run test:radio` отдельно декодирует несколько секунд каждого официального потока с таймаутом и включённой проверкой TLS. `npm run test:radio:voice -- path/to/fixtures.json` проверяет распознавание названий текущим Whisper; манифест содержит `[{"file":"retro.wav","stationId":"retro-fm"}]`, WAV-пути разрешаются относительно него. Также можно задать `RADIO_VOICE_TEST_FIXTURES`. Проверка не подключается к Discord и не печатает расшифровки. Синтезированные примеры не заменяют проверку живой речи после сигнала.

`npm run test:voice` отдельно проверяет настоящую Laya на русских командах, коротких русских/английских вариантах переключения и старом обученном контракте маршрутизации. Цепочка заказа проверяется отдельно: извлечённые названия, исполнители и описания получают первый результат без выбора кандидата моделью. Печатаются решения, уверенность и задержка. Для проверки Whisper задайте `VOICE_TEST_FIXTURES` — путь к локальному JSON-манифесту, например `[{"file":"wake.wav","wakeName":"Муза"},{"file":"next.wav","action":"skip"}]`. Для заказа музыки используйте `{ "file": "song.wav", "musicQuery": "Монеточку" }`: проверяется извлечённый запрос без настоящего поиска, регистр и пунктуация при сравнении игнорируются. WAV-пути разрешаются относительно манифеста; звук декодируется FFmpeg в памяти, расшифровки не печатаются. Синтезированная речь проверяет работоспособность цепочки, но не заменяет проверку настоящих голосов в Discord. `npm run test:integration` дополнительно проверяет выдачу нескольких кандидатов YouTube.

`npm run test:tts` после `setup:tts` проигрывает все настоящие фразы TTS через тот же плеер и Opus-кодер в локальный тестовый приёмник: проверяются слышимый звук, неизменность кэша, сохранение музыкального ресурса, пауза, возобновление и отмена. В Discord эта проверка ничего не отправляет.

## Учебные логи NLI

Если голосовой обработчик зависает или завершается, бот временно отключает своё прослушивание в Discord (перечёркнутый значок наушников), сохраняя воспроизведение. Он автоматически делает до трёх попыток перезапуска с задержками 5, 10 и 20 секунд и восстанавливает ранее включённое прослушивание. Явное `/voice off` остаётся выключенным. Причина сбоя, операция, время ожидания и код завершения записываются в диагностический журнал без текста речи и аудио. Если восстановление не удалось, повторите `/voice on` после снижения нагрузки на видеокарту.

Установите `VOICE_NLI_LOG=1` в `.env` и перезапустите бота. По умолчанию запись выключена. Отдельные JSONL-файлы появляются в `.runtime/nli/commands-YYYY-MM-DD-N.jsonl`: дата UTC, новый файл после 10 МиБ. Старые файлы автоматически не удаляются. Каталог игнорируется Git.

Записываются только распознанные команды после сигнала: исходный текст STT, текст после приведения коротких команд, состояние плеера, версия моделей, решение и уверенность выбранного обработчика, извлечённый запрос, этапы поиска и фактический исход (`changed`, `no_op`, `rejected`, `cancelled`, `failed`). Аудио, обращения до сигнала и идентификаторы говорящего не сохраняются. Обычные диагностические логи по-прежнему не содержат расшифровок. Сбой записи не влияет на выполнение команды.

Каждая запись имеет `event_id`, `state`, `questions`, `gold: null`, `suggested_intent` и `label_status: unreviewed`. Предположение бота и успешно выполненное действие не являются правильной обучающей меткой. Просмотрите текст и задайте метки отдельно, например в `.runtime/reviewed.jsonl`:

```json
{"event_id":"UUID из журнала","intent":"skip"}
```

Допустимые метки: `play`, `radio_play`, `skip`, `pause`, `resume`, `stop`, `volume_set`, `volume_up`, `volume_down`, `autoplay_on`, `autoplay_off`, `loop_on`, `loop_off`, `queue_clear`, `voice_on`, `voice_off`, `unknown`. Экспорт только вручную размеченных записей в формат строк `state/questions/gold`:

```bash
npm run export:nli -- .runtime/reviewed.jsonl .runtime/nli-reviewed.jsonl
```

Экспорт отклоняет неверные/повторные метки и отсутствующие события, не перезаписывает существующий файл. В обучающий `state` попадает исходный текст STT; приведённая команда остаётся только в журнале, чтобы не подсказывать модели правильный ответ. Для новой версии схемы обучения адаптируйте вопросы и метки; запись журнала сама по себе не обучает Laya. Эти примеры предназначены для NLI: исправление ошибок STT требует отдельной проверки распознавания, аудио в этом журнале нет.

В проверке тяжёлого checkpoint `laya-muz-bot-controls-v4` управление плеером прошло 61/61 текстовых примеров, но старый контракт маршрутизации заказа ошибочно выбрал прямую ссылку для «включи Numb» (уверенность 0,769). Этот контракт рабочим поиском не вызывается. Новый лёгкий обработчик на тестовом компьютере потреблял около 417 МиБ RAM, медиана ASR составила 1,58 секунды; бот без включённого прослушивания — около 80 МиБ. Установщик прошёл полный запуск на Windows с уже установленными Node.js и Python; установка этих системных программ на чистой Windows отдельно не проверена. Синтетика не заменяет проверку настоящей речи.
