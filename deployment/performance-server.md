# Замеры ocenochka-server, 4 октября 2026

## После ускорения голосового ввода

Бот обновлён и запущен с заранее подготовленными INT8-весами той же Whisper small.
Прогрев больше не переопределяет окно лёгкого профиля полными 30 секундами.
Окно команд начинается с 15 секунд и увеличивается для длинных записей.
Вариант с окном 8 секунд отклонён из-за двух ошибок на контрольном наборе.
Дополнены варианты названия ENERGY «Энергии» и «Энергию».

Обычный расход RAM во время эфира и команд — 587–636 МиБ. Улучшение касается
загрузки и задержки при эфире; общий пик памяти не уменьшился. На CPU во время
распознавания приходилось 71–97% одного ядра. Сервер остаётся близок к пределу
памяти, но три совместные проверки больше не показывали прежнюю задержку 17 с.

Итог: 137 автономных тестов, 15 Python-тестов, 12/12 радиопримеров и 20/20
примеров управления и обращения прошли. В Discord повторно проверены две
станции, переключение, пауза, возобновление и остановка. Проверка выполнялась
на синтетической речи; речь человека и субъективное качество звука не проверены.
Эти замеры показывают ASR после записи, без ожидания конца фразы, поиска песни
и голосового подтверждения. Путь INT8-модели сохранён в закрытом `.env`
и манифесте подготовки; служба `muz-bot` работает с автозапуском.

## Первоначальные замеры установки

Ubuntu 24.04, один vCPU, 961 МиБ RAM и 2 ГиБ swap. Бот работает в
`/srv/muz-bot-ds` под `muzbot`, Node.js 24.21.0, Whisper small / CPU INT8 /
один поток, короткие готовые ответы. Служба `muz-bot` включена в автозапуск;
вход в Discord подтверждён, перезапусков при проверке не было.

| Измерение | Результат |
| --- | --- |
| Ожидание, RAM процесса бота | 118,2 МиБ |
| Ожидание, CPU за 10 секунд | менее 0,01% |
| Радио с загруженным голосовым обработчиком, RAM дерева процессов | 580–598 МиБ |
| Пиковая RAM дерева процессов в совмещённой проверке | 673 МиБ |
| Радио, средний CPU в двух интервалах по 10 секунд | 16,1% и 39,4% одного CPU |
| ASR без эфира, медиана: команды / радио | 2,19 / 2,21 секунды |
| ASR обращения «Бот» без эфира | 0,57 секунды |
| ASR одной радиокоманды во время эфира | 17,26 секунды; до оптимизации прогрева 23,27 секунды |
| Загрузка голосового обработчика в последнем запуске | 89,22 секунды |
| Свободный диск после установки | 238 МиБ |

Сокращение окна команд small с 30 до 15 секунд уменьшило медиану ASR
примерно с 6 до 2,2 секунды. Тяжёлые модели сохраняют полное окно.
Whisper base давала около 1,9 секунды, но прошла только 10/12 радиопримеров
и 17/20 проверок управления и обращения; beam search улучшил второй результат
до 18/20. Поэтому установлен более точный small. Профиль heavy не установлен
на этом малом VPS.

Проверки: build; 137 автономных TypeScript-тестов; 12 Python-тестов; готовые
голосовые ответы; поиск, аудио и рекомендации YouTube; все 10 официальных
радиопотоков с проверкой TLS; 12/12 синтетических радиопримеров и 20/20 примеров
управления и обращения. В свободном канале Discord проверены две станции,
смена эфира, пауза, открытие свежего эфира при возобновлении, пропуск и очистка.
Распознавание выполнялось одновременно с эфиром; речь человека и субъективное
качество звука пока не проверялись.

Текстовое управление и воспроизведение прошли проверки. Голосовой режим
на этом VPS ограничен памятью: во время совместной проверки использовался
swap, росло ожидание дискового ввода-вывода. Отдельная быстрая проверка ASR
не отражает задержку во время эфира. Поэтому сервер нельзя считать комфортным
для голосового управления, несмотря на успешные функциональные проверки.

Milana и её служба удалены. Две внешние резервные копии Milana сохранены.
Службы nginx и Docker работают; системный Node.js других приложений сохранён.
Токен находится в закрытом `.env` с правами `600` и в отчёт не включён.
