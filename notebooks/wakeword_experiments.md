# Проверка улучшенного wake-word обучения

Дата: 2026-10-05. Итоговый файл: [wakeword_bot_kaggle.ipynb](wakeword_bot_kaggle.ipynb).
Все цифры ниже получены локально на RTX 3070. Полный Kaggle-рецепт ещё не запускался:
он генерирует около 80 800 окон и обучает до 100 эпох на T4 ×2.

## Что проверено

Четыре локальных нейросетевых TTS: Silero v4/v5.5/v3_en, Piper, MMS/VITS, Kokoro.
66 сочетаний модель/голос, 61 группа голоса. Русский train: два Silero,
три Piper, один MMS; две версии одного голоса всегда остаются в одном split.

Эксперимент: 15 496 двухсекундных WAV; train 9462, validation 1734,
calibration 1734, test 2566. В test 528 обращений, 2038 негативных окон,
912 исходных аудио/фоновых групп и 85 групп говорящего, включая 9 TTS-групп.
Варианты одного исходника коррелируют; число окон не равно числу независимых людей.

Все три варианта в таблице используют одинаковые WAV и split; отличаются признаки
и модель. Порог и лучшая эпоха выбираются без test. Основная цель calibration/validation:
FPR ≤ 0.5% в целом и отдельно для RU/EN. Применяется точное сравнение `score >= threshold`.

| Метод | Validation macro recall | Худший язык | Выбранные seed |
|---|---:|---:|---|
| CNN, balanced RU | 38.4% | 32.1% | [0] |
| Google speech embeddings | 34.9% | 32.3% | [1] |
| Whisper Tiny encoder | 64.9% | 62.1% | [0, 1] |

До этого проверялся также вариант CNN с другим распределением русских голосов.
Его validation содержит другого диктора, поэтому его процент не включён
в прямое сравнение архитектур. Простое увеличение эпох не устранило переобучение.

## Сопоставление с присланным V1

На одинаковом test, у V1 с исходным порогом из ZIP:

| Модель | Правильно найдены обращения | Recall | Ложные срабатывания |
|---|---:|---:|---:|
| V1, исходный порог | 50/528 | 9.5% | 10/2038 (0.49%) |
| V4, порог по своему calibration | 336/528 | 63.6% | 20/2038 (0.98%) |

Дополнительный единый протокол заново калибрует оба порога на одинаковом calibration
с ограничением RU/EN/overall. Тогда V1 на test находит 4/528
(0.76%), FP 1/2038; V4 остаётся с результатом выше.
Это сравнение ограничений calibration; фактические test FPR у моделей различаются.
Порог не подбирался для уравнивания ошибок на test.

Русский V4: 109/192 обращений
(56.8%), FP 17/640
(2.66%).
Таким образом цель 0.5% **на test не достигнута**, особенно для русского языка.
V4 улучшает обнаружение и precision, но не является проверенным рабочим детектором
для реального Discord. Основные ошибки — созвучные короткие слова и новые голоса.
Для дальнейшего улучшения предусмотрен `REAL_WAKE_MANIFEST` с вручную проверенными
реальными обращениями/негативами и отдельными людьми в test.

Часть голосов test aidar/en_20–23 уже была просмотрена в V1. Добавленные TTS/реальные
отрицательные слова расширяют benchmark, но он не является полностью слепым.
Реальные положительные записи и длительные разговоры/музыка не тестировались.
FPR/window не переводится в ложные активации в час.

## Инженерная проверка

Итоговый ноутбук выполнен сверху вниз в SMOKE на одном локальном GPU:
все четыре TTS, обучение с FP16, calibration, PyTorch/CPU ONNX parity,
повторная загрузка в отдельном процессе и графики. Отдельно выполнены два CPU
Gloo-процесса с backward, mining и продолжением checkpoint. Две физические GPU
локально не проверены; handoff требует T4 ×2 и использует NCCL DDP.
10 офлайн-проверок проходят. В handoff нет результатов SMOKE или API-ключей.

V4 содержит только акустический encoder и бинарную голову, без decoder.
Дообучаются два последних encoder-слоя; разные LR, EMA, баланс языков/движков,
сложные негативы, умеренные аугментации, mining только train, два seed,
выбор отдельной модели/ансамбля по validation. Для legacy/CNN/Google embeddings
есть отдельные параметры для сравнения, без подмены недоступных движков.

Артефакты эксперимента и машинные отчёты находятся в игнорируемой
`.runtime/wakeword-v4-local/`; обученная модель не подключена к боту автоматически.
